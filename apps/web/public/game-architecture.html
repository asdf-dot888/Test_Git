원정 진행 저장

React ↔ 브라우저 localStorage

현재 덱, 전투 상태, 지도 진행, 타이머를 이 브라우저에 저장합니다. 다른 PC와 자동 동기화되지 않습니다.

랭킹 저장

React → Entra 토큰 검증 API → Cosmos DB

전투 승리 때 완료 전투 수를 제출합니다. API는 토큰에서 직원 ID와 이름을 얻고, 직원별 최고 기록을 저장합니다.

배포 구조: Azure Static Web Apps가 React 정적 파일과 랭킹용 관리형 Functions API를 함께 제공합니다. 별도 App Service는 현재 배포 경로에 포함되지 않습니다.

2. 폴더별 역할

코드가 어디에 있는지 알면 기능을 고칠 위치도 쉽게 찾을 수 있습니다.

packages/game-core/src

게임 규칙의 중심. 카드 목록과 타입, 전투 처리, 원정 상태 전이를 담당합니다.

apps/web/src

React 화면과 브라우저 동작. UI 컴포넌트, 인증, 로컬 진행 저장, 효과음, 타이머가 있습니다.

apps/leaderboard-api/src

운영 랭킹 API. Entra 토큰 검증, 입력 검사, Cosmos DB 읽기·쓰기를 담당하는 Azure Functions입니다.

apps/api/src

Express 기반 게임 진행 API 골격. 현재 React 진행 저장 흐름은 이 서버를 호출하지 않고 localStorage를 사용합니다.

apps/web/public

카드·영웅 이미지와 배경 음악, 효과음 등 브라우저가 직접 불러오는 정적 자산입니다.

scripts/ · docs/

Azure 배포와 릴리스 패키징 스크립트, 설정·문제 해결 안내 문서가 있습니다.

3. 게임 플레이 흐름

화면은 입력을 받고, 엔진은 규칙에 맞는 새 상태를 만들어 냅니다.

원정 만들기

시드와 시작 덱을 정하고 3개 페이즈, 총 12전의 지도 상태를 만듭니다.

카드 전투

React가 액션을 전달하고 game-core가 마나, 카드 효과, 양쪽 하수인 공격을 판정합니다.

승리와 보상

전투가 끝나면 승리 화면, 카드 보상 선택, 다음 전투 지도로 순서대로 이동합니다.

원정 완료

3페이즈 보스를 이기면 원정이 끝납니다. 전투 승리 기록은 랭킹 API로 전송됩니다.

4. 엔진이 처리하는 규칙

전투 화면에서 버튼을 눌러도 결과를 임의로 바꾸지 않고 엔진의 규칙을 통과해야 합니다.

원정 구성

페이즈마다 일반전 3회 뒤 보스전 1회가 이어집니다. 일반 적은 목록에서 선택되고, 페이즈 보스는 정해진 순서로 등장합니다.

마나와 카드

각 전투는 플레이어 마나 5로 시작하고 최대치는 10입니다. 턴 종료 시 현재 턴 구간에 따라 1·2·3 마나가 회복됩니다. 카드 비용을 낼 때 현재 마나가 줄어듭니다.

손패와 덱

덱은 섞여 진행됩니다. 손패가 넘칠 때는 새로 뽑은 카드 중 버릴 카드를 직접 선택합니다. 버림 더미를 다 쓰면 원래 덱을 다시 섞어 채웁니다.

하수인 전투

하수인은 소환한 턴에는 공격하지 못하고, 한 턴에 한 번 공격합니다. 맞은 하수인도 자기 공격력만큼 반격 피해를 줍니다.

적 AI와 보스

적은 성격별 덱과 전술로 카드를 선택하고 하수인으로 공격합니다. 보스는 카드 행동 뒤 3턴마다 광역 피해 패턴을 사용합니다.

연출과 시간

적의 행동은 순서대로 재생되며 행동 사이에 간격이 있습니다. 플레이어 턴에는 제한 시간이 있고, 메뉴나 숨겨진 브라우저 탭에서는 멈춥니다.

5. 로그인과 API 인증

로그인한 브라우저라고 API가 자동으로 신뢰하지 않습니다. 랭킹 API가 Entra 액세스 토큰을 직접 검증합니다.

브라우저 로그인

  1. MSAL이 Entra 로그인 화면을 엽니다.
  2. 랭킹 호출 시 api://<SPA Client ID>/leaderboard.access 범위의 액세스 토큰을 요청합니다.
  3. 브라우저는 토큰을 X-Leaderboard-Access-Token 헤더로 API에 전달합니다.

API에서 확인

  1. 서버는 Entra 서명 키로 토큰 서명을 검증합니다.
  2. 테넌트, 발급자, 대상 API, 만료, leaderboard.access 범위를 확인합니다.
  3. 기록할 직원 ID와 이름은 요청 본문이 아니라 검증된 토큰에서 가져옵니다.

프런트엔드의 VITE_ENTRA_TENANT_ID와 VITE_ENTRA_CLIENT_ID는 공개 식별자입니다. Cosmos 키 같은 비밀값은 브라우저 번들에 두지 않고 Azure API 설정에만 둡니다.

8. 실행과 배포

저장소 루트에서 실행하는 명령입니다.

브라우저에서 개발

npm install 후 .env에 Entra Tenant ID와 Client ID를 설정하고 npm run dev를 실행합니다. 기본 개발 주소는 http://localhost:5173이며, 일반 게임 진행은 Cosmos 연결 없이 브라우저에서 테스트할 수 있습니다.

검증과 Azure 배포

npm run build는 공통 엔진, API 패키지, 웹 앱을 빌드합니다. npm run deploy:swa는 웹 파일과 독립 의존성을 포함한 랭킹 Functions API를 Static Web Apps에 배포합니다.

현재 사용자 원정 진행은 localStorage 저장이므로, 랭킹에 기록된 최고 진행도와 이어하기 데이터는 별개입니다. 랭킹은 서버에 공유되지만 원정 덱·현재 전투 상태는 서버로 올라가지 않습니다.
