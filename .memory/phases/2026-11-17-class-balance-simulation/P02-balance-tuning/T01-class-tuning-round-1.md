# Task: T01 Class Tuning Round 1

## Status: done

## Goal
Use the baseline report to apply a first, small set of numeric changes that move the class gap toward ±5pp.

## Decision Summary
- D05: numeric values only. Card IDs, names, art keys, effect kinds, fusion recipes, and hero power mechanics stay unchanged.
- Tune the strongest outlier down and the weakest outlier up, small steps, measured each round.

## Implementation
### I01. Choose changes from the baseline
- Read `docs/balance/2026-11-17-baseline.md`. Identify the class with the highest and lowest metric (per the judging rule) and the encounters where each loses most.
- Write the chosen change list with a one-line reason each into `docs/balance/2026-11-17-round1.md` (before the measured result).
### I02. Allowed levers, in priority order
1. Hero power numbers in `packages/game-core/src/engine.ts` `useHeroPower`: warrior armor amount (`battle.playerArmor += 2`), assassin damage (`2`), demonist soul-shard threshold (`soulShards < 3` / `soulShards -= 3`; also the `Math.min(6, ...)` cap in `removeDeadMinions`). Hero power mana cost (`2`) may change only as a number, if one class is clearly off.
2. Class minion stats in `packages/game-core/src/catalog.ts` `CLASS_CARD_CATALOG`: attack/health/cost arguments of `minion(...)`. Candidate hypotheses to test: warrior `warrior-vanguard` (1/4 at cost 1) and `warrior-shield-maiden` over-efficient; demonist `demonist-hellbound-adept` (2/2 at cost 2) underpowered; assassin 2-health minions fragile.
3. Class spells (`warrior-*`, `assassin-*`, `demonist-*` `spell(...)` amounts).
4. Fusion result stats (`warrior-fused-bulwark`, `assassin-twinfang`, ...) only if fusion-heavy builds skew results.
- Change budget per round: at most 6 numeric edits, each by at most ±1 on a single stat (cost, attack, or health) or ±1 on a spell/hero-power number.
- Do not touch shared base cards in this task (they affect every class equally) unless a shared card is the clear driver.
### I03. Keep descriptions consistent
- Card descriptions are generated by `describeMinionEffect` / `describeSpellEffects` from the data, so no text edits are needed for stat changes. If a hero power number changes, update the matching `heroPowerDescription` string in `PLAYER_CLASS_DEFINITIONS` and any docs that quote it (search the repo for the old wording, including `apps/web/src` guide text and `README.md`).
### I04. Tests
- Update `packages/game-core/src/engine.test.ts` and any `apps/web/src/**/*.test.tsx` expectations only where a changed number is asserted; do not weaken unrelated assertions.
### I05. Re-measure
- `npm run balance:sim -- --runs <same as baseline> --label round-1 --out docs/balance/2026-11-17-round1.md` and record the before/after table plus gap verdict in that file.

## Acceptance Criteria

- [ ] Round-1 report shows the class gap vs the baseline, per difficulty.
- [ ] All tests, lint, and build pass.
- [ ] Hero power description text matches the code if a hero power changed.
