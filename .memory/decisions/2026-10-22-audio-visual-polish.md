# Decisions: 전투 오디오와 영웅·적 시각 효과 개선

- Date: 2026-10-22
- Status: Confirmed

## D01. 배경 음악
- **Chosen**: 일반 전투용과 보스전용 배경 음악을 각각 재생한다. 전투 종류에 따라 해당 곡으로 전환한다.
- **Rationale**: 사용자는 일반 전투와 보스전에 어울리는 음악을 구분하기로 했다.

## D02. 전투 효과음
- **Chosen**: 영웅 공격, 하수인 공격, 주문, 회복, 피격, 사망에 맞는 효과음을 구분해 재생한다.
- **Rationale**: 전투 동작과 결과를 소리로 알아보기 쉽게 한다.

## D03. 오디오 파일과 설정
- **Chosen**: 사용 허가가 명확한 오디오 파일을 게임에 포함한다. 외부 오디오 URL에 의존하지 않는다.
- **Chosen**: 설정에서 배경 음악과 효과음 볼륨을 각각 조절하고 전체 음소거할 수 있게 한다.
- **Chosen**: 볼륨 설정은 브라우저에 저장해 다음 방문에도 유지한다.
- **Rationale**: 사용자는 파일 기반 오디오와 저장되는 개별 볼륨 설정을 선택했다.

## D04. 게임 메뉴 및 진행 포기
- **Chosen**: 전투 화면의 메뉴 버튼을 누르면 `설정`, `메인 메뉴`, `돌아가기` 선택지를 보여준다. `돌아가기`는 전투로 복귀한다.
- **Chosen**: `설정`에서 배경 음악·효과음 볼륨과 전체 음소거를 조절한다. 설정에서 돌아가면 메뉴 선택지로 복귀한다.
- **Chosen**: `메인 메뉴`를 선택하면 진행 포기 확인을 보여준다. 확인하면 현재 진행을 포기하고 메인 메뉴로 이동하며, 새 게임은 메인 메뉴에서 별도로 시작한다. 취소하면 메뉴 선택지로 돌아간다.
- **Rationale**: 사용자는 메뉴에서 세 가지 동작을 선택하고, 메인 메뉴로 이동할 때 진행을 포기하도록 결정했다.

## D05. 적 하수인 시각 구분
- **Chosen**: 적 하수인 이미지 선명도는 플레이어 하수인과 동일하게 유지한다. 적 하수인에는 붉은 테두리와 약한 붉은 광채를 적용하고 적 진영 바닥 표시도 추가한다.
- **Rationale**: 적 진영이라는 점은 더 뚜렷이 보여주되 카드 아트는 흐리게 처리하지 않는다.

## D06. 마나 회복 규칙
- **Chosen**: 최대 마나는 10으로 고정하고 첫 턴은 5/10으로 시작한다. 다음 턴부터 턴이 끝날 때 남은 마나에 1을 더해 회복하되 10을 넘지 않는다. 사용하지 않은 마나는 다음 턴에 이월한다.
- **Example**: 턴 종료 시 5/10이면 다음 턴은 6/10이다.
- **Rationale**: 사용자는 최대 마나를 매 턴 키우거나 현재 마나를 최대로 채우는 대신, 남은 마나가 턴마다 1씩 늘어나는 규칙을 확정했다.

## D07. 영웅 초상화 일러스트
- **Chosen**: 플레이어 영웅은 고정 일러스트를 쓴다. 각 일반 적과 각 보스는 서로 다른 고유 일러스트를 쓴다.
- **Chosen**: 전체 그림체는 카드 아트와 어울리는 어둡고 웅장한 판타지 회화풍으로 한다.
- **Rationale**: 플레이어·일반 적·보스를 구분하고, 각 적의 정체성이 초상화에 드러나게 한다.

## Implementation notes
- 코드상 적 하수인에 CSS 블러가 적용되지는 않는다. 플레이어와 적 하수인은 같은 카드 이미지 요소를 사용하고 적에는 붉은 테두리 클래스가 있다. 요청한 추가 진영 표시는 이 스타일에 더한다.
- 전투 메뉴 버튼은 현재 곧바로 메인 메뉴 화면으로 이동한다. 활성 진행은 서버 저장 상태에 남아 있고 새 게임 시작 시 포기 확인을 거쳐 교체된다. 선택한 흐름에 맞춰 메뉴 선택과 확인 뒤 메인 메뉴 이동을 연결해야 한다.
- 마나 최대치는 현재 이미 10으로 정의되어 있다. 턴 시작 로직은 최대치를 증가시키고 현재 마나를 최대치까지 채우므로, 고정 최대치와 남은 마나 +1 규칙으로 변경해야 한다.
- 프로젝트에 배경 음악 및 효과음 재생 기능이나 오디오 파일은 없다. 오디오 자산을 추가할 때 사용 권한과 출처를 함께 기록한다.
- 현재 활성 메모리 계획의 모든 Task가 완료되어 있다. 이 결정은 새 계획의 입력으로 사용하며, 이 인터뷰 단계에서는 구현하거나 계획 파일을 만들지 않는다.
