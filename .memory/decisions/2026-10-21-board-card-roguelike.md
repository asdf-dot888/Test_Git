# Decisions: 보드형 카드 로그라이크

- Date: 2026-10-21
- Status: Confirmed

## D01. 게임 형식과 화면
- **Chosen**: 어두운 판타지 세계관의 보드형 1인용 카드 로그라이크. 영웅 캐릭터는 보드에 별도로 남고, 사용한 카드는 하수인 또는 주문으로 작동한다. PC와 모바일을 지원하며, 보드와 카드 화면은 일러스트풍으로 구성한다.
- **Rationale**: 사용자가 제공한 보드형 카드 전투 이미지처럼 영웅과 카드가 분리된 구성을 원한다고 명확히 했다.

## D02. 한 판의 진행 구조
- **Chosen**: 총 3페이즈. 각 페이즈는 일반 전투 3회와 보스전 1회로 구성한다. 갈림길 지도는 없고, 각 전투 후 다음 일반 적을 무작위로 배정한다. 각 페이즈마다 보스 1명이 있다.
- **Rationale**: 3회 일반 전투 후 보스전을 반복하는 구조를 사용자가 지정했다.

## D03. 영웅과 승패
- **Chosen**: 플레이어 영웅은 하나, 최대 체력은 30. 영웅 고유 능력과 무기 카드는 넣지 않는다. 영웅 체력이 0이 되면 해당 판을 종료한다.
- **Rationale**: 보드 전투와 카드에 집중하고, 첫 버전의 규칙을 단순하게 유지한다.

## D04. 마나
- **Chosen**: 마나는 카드를 내는 자원이다. 각 전투 첫 턴은 5마나로 시작하고, 매 턴 마나 최대치가 1씩 증가해 10에 도달한다. 턴이 시작되면 사용 가능 마나는 해당 턴의 최대치로 회복한다. 전투가 끝나면 체력과 마나는 다음 전투의 기본값으로 초기화한다.
- **Rationale**: 사용자가 최초 마나 5, 턴마다 증가, 최대 10 규칙을 지정했다. 전투마다 기본값으로 시작한다는 해석을 적용했다.

## D05. 손패와 카드 더미
- **Chosen**: 전투 시작 손패는 3장, 이후 턴마다 1장을 뽑는다. 턴이 끝나도 사용하지 않은 카드는 손에 남는다. 손패는 최대 10장이다. 손패가 가득 찬 상태에서 카드를 뽑기 전 플레이어가 손패에서 버릴 카드를 고른다. 드로우 더미가 비면 고정된 최초 시작 덱 30장을 새 카드 인스턴스로 다시 만들어 무작위로 섞어 드로우 더미에 채운다. 현재 손패·필드·버림 더미의 카드는 그대로 둔다. 전투 보상 카드는 런의 덱과 이후 전투 시작 덱에는 포함되지만, 이 재충전용 최초 30장 목록에는 포함하지 않는다.
- **Rationale**: 사용자는 드로우 더미가 비었을 때 최초 30장 덱을 다시 무작위로 섞어 추가하도록 지정했다. 카드가 손패나 필드에 남아 있어도 재충전은 최초 덱을 기준으로 독립적으로 발생한다.

## D06. 카드 구성과 덱 성장
- **Chosen**: 카드 종류는 총 30개(하수인 20종, 주문 10종). 시작 덱은 고정된 30장이다. 같은 카드는 덱에 최대 2장까지 포함한다. 첫 버전의 카드 이름, 마나 비용, 능력치, 효과는 어두운 판타지 설정에 맞춰 구현자가 설계한다.
- **Rationale**: 카드 종류와 비율, 시작 덱, 복사 제한을 사용자가 선택했다. 카드 수와 보상 선택의 폭을 맞추기 위해 20종에서 30종으로 늘렸다.

## D07. 카드 보상
- **Chosen**: 일반 전투 승리 시 카드 3장 중 1장을 선택하며, 보상을 건너뛸 수 있다. 보스 승리 시 더 강한 카드 3장 중 1장을 선택한다. 보상 단계에서는 기존 카드를 제거하지 않는다.
- **Rationale**: 전투 승리로 덱을 키우되 원하지 않는 카드를 억지로 추가하지 않도록 한다.

## D08. 하수인 전투 규칙
- **Chosen**: 한쪽 필드에 하수인은 최대 5마리. 소환된 하수인은 다음 턴부터 턴마다 한 번 공격한다. 공격력은 현재 체력에 따라 줄지 않고 카드에 표시된 값 그대로 적용한다. 공격 시 공격한 하수인만 피해를 주며 대상은 반격하지 않는다. 상대 하수인이 남아 있으면 영웅 대신 하수인을 공격해야 하고, 상대 필드가 비었을 때 영웅을 공격할 수 있다.
- **Rationale**: 사용자가 보드 전투의 공격 가능 시점, 피해 규칙, 대상 우선순위를 선택했다. 도발은 대상 제한 규칙과 중복되어 제외한다.

## D09. 주문과 특수 효과
- **Chosen**: 주문의 대상은 카드 효과에 따라 플레이어가 고른다. 하수인 특수 능력은 소환·강화 같은 단순 효과를 일부 포함하며 도발은 포함하지 않는다.
- **Rationale**: 첫 버전은 읽기 쉬운 카드 효과를 중심으로 두고, 적 하수인을 먼저 공격하는 규칙과 충돌하는 효과는 제외한다.

## D10. AI 적과 보스
- **Chosen**: 싱글 플레이 AI 상대. 일반 적은 6종, 보스는 3종이다. 각 적의 턴에는 플레이어 영웅에게 피해를 주거나 적 하수인을 소환하는 행동 중 하나를 무작위로 실행한다. 행동 종류와 이번에 선택된 행동은 모두 플레이어에게 숨긴다. 적 하수인은 플레이어 하수인과 같은 공격 규칙을 따른다. 보스는 일반 적보다 체력이 높고 고유 행동을 갖는다.
- **Rationale**: 사용자가 카드 규칙을 따르는 AI 대신 정해진 행동 목록에서 무작위로 행동하는 적을 선택했다. 보스전은 각 페이즈의 고유한 마무리 전투로 만든다.

## D11. 전투 사이와 판 종료
- **Chosen**: 각 전투가 끝나면 영웅 체력과 마나를 기본값으로 회복한다. 덱은 한 판의 3페이즈 동안 유지한다. 패배하면 판을 종료하고 다음 판은 고정 시작 덱 30장으로 시작한다. 보스 3명을 모두 이겨도 영구 해금이나 능력치 성장은 없다.
- **Rationale**: 사용자가 매 전투 종료 후 체력·마나 회복과 3페이즈 구성을 지정했다. 매 판의 차이는 판 안에서 획득한 카드와 선택에서 생긴다.

## D12. 로그인과 접근 제한
- **Chosen**: 사내 Microsoft Entra ID 테넌트 계정만 허용한다. 로그인하지 않은 사용자는 Azure 호스팅 단계에서 앱에 접근할 수 없다. 로컬 개발에서도 사내 Entra ID 로그인을 사용한다.
- **Rationale**: 게임 접근에 사내 ID 로그인이 필요하다는 요구를 충족한다.

## D13. 애플리케이션과 Azure 구성
- **Chosen**: React 프런트엔드와 Node.js + TypeScript API를 같은 Azure App Service에 배포하고, Azure Cosmos DB를 사용한다. 로그인한 사용자는 계정에 진행 중인 판을 저장해 다른 기기에서도 이어할 수 있다.
- **Rationale**: 기존 인터뷰에서 선택한 Azure 환경과 게임 진행 저장 요구를 새 보드형 게임에도 적용한다.

## D14. 저장 범위와 세션 관리
- **Chosen**: 계정당 진행 중인 판 하나만 저장한다. 주요 게임 행동 후 자동 저장한다. 한 계정은 한 기기에서만 플레이할 수 있고, 15분 동안 입력이 없으면 잠금을 해제한다. 새 판을 시작할 때 기존 판이 있으면 포기 여부를 먼저 확인한다. 저장 데이터는 진행 중인 판에 한정한다.
- **Rationale**: 다른 기기에서 이어하기를 지원하면서 동시에 진행되는 판의 저장 충돌을 막는다.

## D15. 구현상 결정
- **Chosen**: 시작 덱 30장과 30종 카드 풀의 구체적인 카드 구성은 최대 2장 제한과 20:10 하수인/주문 비율에 맞춰 작성한다. 무작위 AI 행동 중 보드가 가득 차 실행할 수 없는 소환 행동은 가능한 행동에서 제외한다.
- **Rationale**: 사용자가 카드 효과 설계를 위임했고, 카드 복사 제한과 필드 크기가 정해져 있다. 유효하지 않은 상태 전이를 막기 위한 구현 규칙이다.
